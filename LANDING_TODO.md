# Что обещает главная страница и что для этого достроить

Лендинг (`resources/views/welcome.blade.php`, тексты в `lang/*/landing.php`) написан под
целевой продукт, а не под текущий срез кода. Часть обещаний уже работает, часть — нет,
и помечена на странице бейджем «Скоро».

Правило простое: **у каждого бейджа «Скоро» на странице есть строка в этом файле, и наоборот.**
Когда функция готова — удаляете `'soon' => true,` из соответствующего ключа в
`lang/ru/landing.php` и `lang/en/landing.php`, вычёркиваете строку здесь. Бейдж исчезает,
переписывать секцию не нужно.

Проверить расхождения:

```bash
grep -c "'soon' => true" lang/ru/landing.php lang/en/landing.php   # должно совпадать
grep -n "'soon' => true" lang/ru/landing.php                       # что ещё помечено
```

## Секция «Что входит бесплатно»

### 1. Приложение для клиенток
`landing.free.items.app` · `landing.booking.items.app`

**Есть:** Expo/React Native в `Client Mobile App/`. Вход по email + OTP работает против
живого API (`ClientPortalAuthService`), брендовая палитра на месте (`src/theme/theme.ts`),
токен хранится в `expo-secure-store`. Экранов три: Splash, Auth, Home.

**Достроить:**
- [ ] Экраны каталога услуг, выбора слота и подтверждения записи. API уже готов:
      `GET /client/services`, `GET /client/slots`, `POST /client/appointments`.
- [ ] Кнопки на `HomeScreen.tsx` — сейчас `onPress={() => {}}`, заглушки.
- [ ] Экран истории визитов (нужен новый роут, см. пункт 3).
- [ ] Подтягивать бренд мастера с API вместо `masterLandingMock` в `mocks/mockClientPortal.ts` —
      без этого приложение не «под вашим именем», а с зашитым демо-салоном.
- [ ] Сборка и публикация.

### 8. Уровни лояльности
`landing.retention.items.loyalty`

**Есть:** `Client::loyaltyFromVisits()` уже написан и покрывает

**Достроить:**

Самая дешёвая позиция в списке: логика есть, нужен один вызов.

**Достроить:**

## Не на лендинге, но в очереди

Эти вещи странице ничего не обещают — просто зафиксировано, чтобы не потерялось.

- [ ] **14 дней «Мастера» при регистрации.** Схема уже умеет: `activePlanSlug()` берёт
      самый дорогой план с `ends_at` в будущем. Достаточно привязать `pro` с
      `ends_at = now()->addDays(14)` при создании аккаунта. Новая логика не нужна.
- [ ] **Годовая оплата со скидкой.** Периодов подписки в коде нет — `YooKassaService`
      умеет только разовый платёж за план. Это отдельная задача, и до неё лендинг
      про годовую оплату молчит.
- [ ] **Портфолио до/после.** Модель `Media` есть, кода нет. Сильно усилило бы сайт мастера.
- [ ] **Голосовые заметки о визите.** Модель `VoiceNote` есть, кода нет.
- [ ] **Синхронизация с Google Календарём.** В коде отсутствует полностью.
- [ ] **`AnalyticsDaily`** (`margin_per_hour`, `repeat_rate`) — осиротевшая модель, в неё
      никто не пишет и из неё никто не читает. Либо заполнить, либо удалить.
      Из-за неё в `lang/*/dashboard.php` висит неиспользуемый ключ `finance.services.insight`
      про «маржу за час» — на лендинге эту формулировку сознательно не используем,
      там маржа считается по услуге (цена минус себестоимость), и это правда.

## Мёртвый код, который легко принять за фичу

Проверено, задокументировано в `AGENTS.md`. На лендинге не заявлено — и не надо.

- `app/Services/DashboardAiService.php` — полностью написан, с вызовами OpenAI,
  **не инстанцируется нигде**. Главный экран целиком на правилах.
- `app/Services/UsefulDigestService.php` — вопреки названию **не вызывает ни одну модель**,
  это чистая курация контента.

Поэтому в текстах лендинга слово «ИИ» стоит только там, где ИИ действительно работает:
тексты клиенткам, рекомендации услуг, идеи для постов, разбор клиентской карточки.
Про главный экран и прогноз неявки написано «считает по вашей истории» — это и вернее,
и убедительнее.
